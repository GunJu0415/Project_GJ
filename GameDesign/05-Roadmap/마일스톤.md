# 마일스톤

문서에 **실제로 쓰인 표기만** 정리한다. 출처는 `Docs/superpowers/specs/`의 각 설계 문서와 `Docs/DevGuide.md`다.
지금 무엇이 되는지는 [[현재 상태]], 할 일 목록은 [[백로그]].

## 전체 지도

`Docs/superpowers/specs/2026-08-08-run-loop-design.md`에 그려진 의존 트리가 원본이다.

```
전투 스탯 + 데미지 공식        (번호 없음, M2의 전제)
M1 런 루프 닫기
 ├─ M2 인런 성장 (EXP/레벨업)        — 언제 리셋되는지가 M1에서 결정됨
 │   ├─ M2.5 스탯 보너스 레이어
 │   ├─ M2.6 카드 선택 시스템
 │   └─ M2.7 액티브 스킬 시스템
 ├─ M3 회차 인계 규칙                — 무엇이 남는지를 정의
 │    └─ M4 세이브/로드              — RebirthCount와 M3의 인계 대상을 영구 저장
 │         └─ M6 메타 프로그레션
 └─ M5 스테이지 진행 (다중 레벨)      — 런에 구조 추가, 클리어 조건 도입

M7 근접 무기 + 히트 판정  ← 독립적, 순서 무관
```

**세로줄이 두 개다.** 왼쪽(M3→M4→M6)은 "런을 넘어 무엇이 남는가", 오른쪽(M5)은 "런 안에 어떤 구조가 있는가". 둘은 서로를 기다리지 않는다.

## 마일스톤 표

| 표기 | 이름 | 상태 | 근거 |
|---|---|---|---|
| — | 전투 스탯 + 데미지 공식 | **완료** | 08-12 `공격 계산 연결로 데미지 공식 완성` |
| **M1** | 런 루프 닫기 | **완료** | 08-12 `허브에 런 시작 포탈 추가로 로그라이트 루프 완성` |
| **M2** | 인런 성장 (EXP/레벨업) | **완료** | 08-13 `HUD에 경험치 바와 레벨 표시 추가` |
| **M2.5** | 스탯 보너스 레이어 | **완료** | 08-13 `스탯을 테이블 원본/보너스/실효값 3층으로 분리` |
| **M2.6** | 카드 선택 시스템 | **완료** | 08-17 `레벨업에 카드 선택 연결, 효과 적용과 무기 교체 추가` |
| **M2.7** | 액티브 스킬 시스템 | **완료** | 08-18 `MP 부족할 때 스킬 아이콘에 파란 틴트`까지 (스킬 상태 표시 포함) |
| **M3** | 회차 인계 규칙 | 미착수 | `bPersistAcrossRuns`가 필드만 존재 |
| **M4** | 세이브 / 로드 | 미착수 | `RebirthCount`가 앱 종료 시 사라짐 |
| **M5** | 스테이지 진행 (다중 레벨) | 미착수 | 런 클리어 조건이 여기서 도입된다 |
| **M6** | 메타 프로그레션 (영구 강화) | 미착수 | 허브에 포탈 하나뿐 |
| **M7** | 근접 무기 + 히트 판정 | 미착수 | 순서 무관, 언제든 가능 |

### 완료된 것에 대한 주석

- **M1은 "닫혔지만 반쪽"이다.** 설계 문서가 스스로 인정한다 — `RebirthCount`는 누적 지표로 설계됐지만 M1은 인메모리라 앱을 끄면 0으로 돌아간다. **M4가 M1의 미완성 부분을 채운다.**
- **M2.5는 M2.6의 전제였다.** 카드가 스탯을 올리려면 "테이블 값 위에 얹는 층"이 먼저 있어야 했다.
- **M2.7의 스킬 UI는 별도 스펙(`2026-08-17-skill-ui-design.md`)이지만 번호가 붙지 않았다.** M2.7에 딸린 작업으로 본다.

### 미착수인 것의 갈림길

- **M3이 먼저 결정돼야 M4가 무엇을 저장할지 정해진다.** M4의 저장 대상 1순위는 `RebirthCount`로 이미 정해져 있다.
- **M6은 화폐 설계와 얽혀 있다.** "골드가 런을 넘어 남는지"가 결정되지 않으면 상점도 영구 강화도 못 짠다 → [[백로그]]
- **M5는 훅이 이미 열려 있다.** 카드 지급 진입점(`GrantCardChoice()`)이 공개돼 있고, `AGJBossRoom`이 오버라이드할 자리도 비어 있다. 부르기만 하면 되는 상태다.

## 룸 시스템 A / B / C

절차적 던전은 마일스톤과 **별개의 축**으로 A/B/C로 쪼개졌다. 출처는 `Docs/superpowers/specs/2026-08-18-room-system-design.md`.

| 단계 | 이름 | 상태 | 내용 |
|---|---|---|---|
| **A** | 룸 하나가 성립 | **완료** (08-20) | 방 하나가 스스로 채워지고, 전멸을 세고, 출구를 연다. 이 프로젝트에 **적 스폰 시스템이 아예 없던 것**을 메운 작업 |
| **A2** | 습득 아이템 종류 | **완료** (08-22) | 회복 아이템 / 대가 지불 아이템. A와 의존이 없어 별도 스펙으로 분리됨 |
| **B** | 절차적 배치 | 미착수 | 방을 여러 개 잇기, 겹침 방지, 시작·보스방 보장 |
| **C** | 스테이지 진행 | 미착수 | 스테이지 넘기기, 런 클리어, `AGJBossRoom` |

### A가 증명한 것

방 종류마다 클래스를 만들지 않는다는 설계가 실제로 시험대에 올랐다. 회복방·상점방·보급방 요구가 들어왔을 때 **방 클래스는 하나도 안 늘었다** — `AGJCombatRoom` + 적 0마리 + 다른 `ItemPool`로 전부 성립했고, 늘어난 것은 아이템 클래스뿐이었다.

**모양과 역할은 다른 축**이라는 것도 여기서 나왔다. 모양은 BP 서브클래스 / 파라미터, 역할은 `DT_RoomSpawn` 행. 둘을 다 BP에 넣으면 `BP_Square_Combat`, `BP_Long_Combat`… 으로 곱셈으로 늘어난다. → [[던전과 방]]

### B가 갚아야 할 빚

A에서 "방은 `BeginPlay`에 채워진다(처음부터 깔려 있게)"로 결정했다. **방이 하나일 때는 안 드러나지만, 던전 전체가 한 번에 채워지면 먼 방의 적도 처음부터 살아서 플레이어를 향해 길찾기를 한다.** 설계 문서가 B에서 반드시 다시 꺼내라고 못 박아 뒀다.

또 B의 전제가 이미 A에 들어가 있다 — `UGJRoomExitComponent`가 출구의 위치와 전방 방향을 들고 있고, `SetSpawnRow(FName)`가 지연 스폰용 진입점으로 열려 있다.

### C와 M5는 같은 것을 가리킨다

C(스테이지 진행 · 런 클리어 · 보스방)와 M5(스테이지 진행 · 클리어 조건 도입)는 두 문서가 각자의 표기로 **같은 작업**을 부르고 있다. 백로그에서는 한 덩어리로 다룬다.

## 순서에 대한 관찰

문서들이 이미 정해 둔 선후 관계만 모으면 이렇다.

1. **B가 C보다 먼저다** — 이을 방이 없으면 스테이지를 넘길 것도 없다
2. **화폐 결정이 상점·M6보다 먼저다** — 골드의 수명이 정해져야 둘 다 설계된다
3. **M3이 M4보다 먼저다** — 무엇이 남는지가 정해져야 저장할 것이 정해진다
4. **M7은 아무 데나 끼워도 된다** — 방어력이 `TakeDamage`에 있어서 새 데미지 소스가 자동으로 경감을 탄다
