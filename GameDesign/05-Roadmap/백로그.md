# 백로그

`Docs/DevGuide.md` 9절(알려진 갭)과 각 설계 문서의 "이후 작업 / 안 하는 것"을 영역별로 모았다.
지금 상태는 [[현재 상태]], 큰 단계 구분은 [[마일스톤]].

우선순위: **P0** 지금 다음에 할 것 / **P1** 그 다음 / **P2** 있으면 좋은 것 / **P3** 나중에

## P0 — 게임이 게임이 되려면 필요한 것

지금 **한 방을 치우고 나면 갈 곳이 없다.** 이 구멍을 먼저 메운다.

### 던전 진행

- [ ] **룸 시스템 B — 절차적 배치**: 방을 여러 개 이어 던전을 생성한다. 지금은 방이 하나뿐이고 손으로 놓아야 해서, 매 런이 같은 방 하나다
- [ ] **먼 방 적 비활성화**: 던전 전체가 `BeginPlay`에 채워지므로 먼 방 적도 처음부터 플레이어를 향해 길찾기를 한다. "플레이어가 일정 거리 밖이면 AI를 꺼둔다" 수준으로 싸게 막는다 — B와 **같이** 해야 한다
- [ ] **방에 문을 여러 개 만들기**: 지금은 북쪽 하나뿐. `AGJBoxRoom::AddDoorway`를 여러 번 부르면 되지만 B가 있어야 의미가 생긴다
- [ ] **방 모양 늘리기**: 긴 복도, L자 등. `AGJBoxRoom` 파라미터라 새 클래스가 아니라 새 BP 값이면 된다
- [ ] **룸 시스템 C / M5 — 스테이지 진행**: `AGJBossRoom`을 만들어 클리어 시 문을 여는 대신 **다음 스테이지로 넘긴다**. 훅(`HandleRoomCleared`)은 이미 열려 있다
- [ ] **승리 조건 (런 클리어)**: 런이 사망으로만 끝난다. `EndRunAndReturnToHub()`가 종료 사유를 받도록 확장하는 것까지 설계에 적혀 있다
- [ ] **스테이지 클리어 시 카드 지급**: 진입점 `GrantCardChoice()`가 이미 공개돼 있어 부르기만 하면 된다
- [ ] **스테이지별 적 스탯 스케일링**: `ApplyEnemyStat`이 테이블 값을 직접 대입한다. `FStatModifier`를 그대로 재사용하면 된다

### 게임 방향 결정 (코드보다 먼저)

- [ ] **골드가 런을 넘어 남는가 결정하기**: **이것이 상점·영구 강화 전부의 갈림길이다.** 남으면 메타 화폐가 되고, 안 남으면 런 안 경제가 된다. 정해지기 전에는 [[아이템 목록]]의 가격도 [[마일스톤\|M6]]도 설계할 수 없다
- [ ] **화폐 시스템**: 위 결정이 난 뒤. 획득처(적 처치? 상자?)와 표시 UI가 함께 필요하다
- [ ] **상점 NPC (`AGJShopNPC`)**: 바닥에 아이템을 까는 대신 **재고 목록을 든 NPC와 상호작용**하는 구조로 가기로 결정됨. `AGJShopItem`은 만들지 않는다
- [ ] **`AGJPricedItem::CanAfford` / `PayPrice` 골드 버전**: 화폐가 생기면 이 둘만 구현하면 되고 지불 흐름은 안 건드린다

## P1 — 런이 이어지게 만드는 것

### 회차 인계와 저장

- [ ] **M3 회차 인계 규칙**: `FItemData.bPersistAcrossRuns`를 실제로 읽는다. 지금은 레벨 재진입으로 전부 초기화되는데, "일부만 남는다"가 로그라이트의 핵심이다
- [ ] **M4 세이브 / 로드**: `USaveGame`. **저장 대상 1순위는 `RebirthCount`** — 지금은 앱을 끄면 0으로 돌아가서 누적 도전 횟수라는 설계가 무의미하다
- [ ] **M6 영구 강화**: 별도 재화 + 별도 저장소로 만든다(런 내 성장과 섞지 않기로 결정됨). M4 이후
- [ ] **`BonusCardSlots` / `ExtraCardChance` 연결**: 카드 선택지를 늘리는 경로가 멤버만 있고 아무도 안 쓴다. 영구 특성이 여기 꽂힌다

### 전투의 빈 축

- [ ] **M7 근접 콤보 히트 판정**: `Attack1`/`Attack2` 몽타주 섹션 점프만 있고 **맞지 않는다.** 지금 실전에서 쓸 수 있는 건 원거리뿐 — 핵앤슬래시를 표방하면서 근접이 없다
- [ ] **근접 무기 클래스**: `AGJWeaponBase` 서브클래스가 필요하다. 슬롯·스왑·픽업은 무기 타입과 무관하게 이미 동작한다
- [ ] **적 종류 늘리기**: 지금 근접 잡몹 한 종류뿐. 원거리 적·엘리트·보스 → [[적]]
- [ ] **적 전용 데스 몽타주**: 지금 사격 몽타주(`MM_Rifle_Fire_Montage`)를 임시 재사용 중
- [ ] **사망 연출**: `OnDeath()` BP 이벤트가 비어 있다

## P2 — 완성도와 손맛

### 스킬

- [ ] **Skill2(Q) / Skill3(F)에 넣을 실제 스킬**: 슬롯·입력 바인딩·교체 UI가 전부 준비됐는데 파이어볼 하나뿐이라 두 칸이 빈다
- [ ] **`ESkillType::Persistent` (지속형 스킬)**: 발사 시 경고만 찍히고 아무 일도 안 일어난다
- [ ] **`CooldownReduction` 연결**: 스탯 필드만 있고 소비처가 없다. **스킬 쿨타임이 가장 자연스러운 첫 후보**로 문서에 적혀 있다
- [ ] **차징 구체 연출**: 발사될 구체 메시를 그대로 키울 뿐이고 이펙트·머티리얼·시전 애니메이션이 없다
- [ ] **스킬 설명 툴팁**: `FSkillData.Description`이 어디에도 안 쓰인다

### 카드

- [ ] **카드 리롤 / 스킵**: 3장이 다 마음에 안 들어도 반드시 하나를 골라야 한다. `DrawCards(Count)`가 부작용이 없어 재호출만으로 되지만 버튼과 횟수 관리가 없다
- [ ] **회복 카드**: 필드 회복(`AGJHealItem`)은 되지만 카드로 회복하려면 `ECardEffectType`에 값 추가가 필요하다
- [ ] **태그 배율을 올리는 주체**: `SetTagWeightMultiplier`가 콘솔에서만 호출된다. "직업 카드"나 "먹은 카드 누적"이 붙으면 둘 다 이 함수로 들어와야 한다
- [ ] **카드 희귀도 시각화**: 확률(`Weight`)로만 존재하고 색 테두리 등 구분이 없다

### UI / 연출

- [ ] **가격표 UI**: 대가형 아이템 가격이 로그로만 보인다. 월드 위젯이 필요한 별도 작업
- [ ] **치명타 표시**: 터져도 화면에 안 보인다. 치명타 여부가 공격자 쪽에만 있어서 커스텀 `FDamageEvent`가 필요하다
- [ ] **레벨업 / EXP 획득 연출**: 팝업·사운드·파티클 없이 HUD 바와 로그뿐
- [ ] **방사형 쿨타임 마스크 머티리얼**: 지금은 위에서 아래로 걷힌다. 머티리얼만 만들면 `WBP_SkillIcon`에서 위젯 교체만으로 끝난다 (**C++ 변경 없음**)
- [ ] **문 열리는 연출**: 블로커 큐브가 그냥 사라진다. `OnRoomCleared`를 BP에서 받아 붙이면 된다
- [ ] **자리표시자 에셋 교체**: 스킬 아이콘·카드 아이콘(`T_GridChecker_A`), HUD 초상화(`T_UE_Logo_M`)

## P3 — 데이터·정리·나중 일

### 임시 데이터 확정

밸런싱은 **[[마일스톤\|M5]] 스테이지 진행이 생긴 뒤에 해야 의미가 있다** — 지금 잡으면 기준이 없다. → [[레벨 곡선]]

- [ ] `DT_CharacterStat` 레벨 2~5 성장 곡선
- [ ] `DT_SkillData` 파이어볼 수치와 `SkillPower` 곡선
- [ ] `DT_CardData` 카드 6장 (검증용 임시)
- [ ] `DT_RoomSpawn` `Combat_Basic` 행
- [ ] 무기 스왑 전용 몽타주 (`SwapMontageAsset` — 비어 있으면 즉시 교체로 정상 동작)

### 코드 정리

- [ ] **`ECharacterState` 중복 값 정리**: `Rolling`/`Dodge`, `Attacking`/`Attack`이 점진적 추가로 생긴 잔재. 실제로 쓰는 건 `Dodge`/`Attack` 쪽
- [ ] **`MyGJWeaponBase` 제거**: 빈 미사용 스텁
- [ ] **GAS 도입 여부 결정**: 모듈만 링크돼 있고 `GetAbilitySystemComponent()`가 항상 null. **쓸 거면 쓰고 아니면 모듈을 빼는 게 낫다** — 지금은 어느 쪽도 아니다
- [ ] **`DropWeapon()` 드랍 위치**: 캐릭터 정면 100유닛 고정. 바닥 스냅도, 다른 물체와 겹침 방지도 없다
- [ ] **모디파이어 개별 제거 / 시간제 버프**: `StatBonus`는 누적만 한다. 10초짜리 버프가 필요해지면 `TArray<FStatModifier>` + 핸들 방식으로 바꾼다. 그때도 `RecalculateStats`만 고치면 되고 실효값을 읽는 코드는 안 바뀐다

## 의존 관계 한눈에

```
골드 수명 결정 ──┬─> 화폐 시스템 ──> 상점 NPC ──> 가격표 UI
                 └─> M6 영구 강화 <── M4 세이브 <── M3 인계 규칙

룸 B (절차적 배치) ──> 룸 C / M5 (스테이지·승리 조건) ──> 스테이지 스케일링
   └ 먼 방 AI 끄기 (B와 동시)                            └ 스테이지 클리어 카드 지급

M7 근접 히트 판정 ── 독립. 아무 때나
```
