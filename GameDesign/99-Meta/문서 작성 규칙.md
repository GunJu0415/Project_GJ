# 문서 작성 규칙

이 볼트를 앞으로 어떻게 유지할지. 짧게.

## 이 볼트가 답하는 것 / 답하지 않는 것

| | 여기 (`GameDesign/`) | `Docs/DevGuide.md` |
|---|---|---|
| 질문 | 게임이 **무엇이고 왜** 그런가 | 코드가 **어떻게** 돼 있나 |
| 쓴다 | 규칙, 의도, 수치의 이유, 콘텐츠 목록, 미정 사항 | 클래스·함수·델리게이트·구현 함정 |
| 안 쓴다 | 클래스명 나열, 함수 시그니처, 구현 순서 | 왜 그런 게임인지 |

**판단 기준**: 그 문장이 코드를 다시 짜도 살아남으면 여기, 코드를 고치면 틀려지면 DevGuide.

구현 세부가 꼭 필요하면 **한 줄로만** 짚고 넘어간다. "무기가 발사 간격을 스스로 판단한다" 정도는 되지만, 함수 이름과 호출 순서는 DevGuide 몫이다.

## 층위

| 층 | 담는 것 | 판단 기준 |
|---|---|---|
| `01-Vision` | 게임의 정체성. 루프. 판단 기준 | 시스템이 통째로 바뀌어도 유지되는 것 |
| `02-Systems` | 시스템별 규칙 | "이 시스템은 어떻게 동작하는가" |
| `03-Content` | 실제로 정의된 적·무기·스킬·카드·아이템 | 데이터 테이블 행에 대응하는 것 |
| `04-Balance` | 수치와 곡선, 그 수치인 이유 | 밸런싱하다 바뀌는 것 |
| `05-Roadmap` | 마일스톤, 백로그 | 아직 없는 것 |
| `99-Meta` | 볼트 자체에 관한 것 | 게임 내용이 아닌 것 |

**새 문서를 어디에 넣나** — 위에서부터 읽어 내려가며 처음 걸리는 곳에 넣는다. 애매하면 더 아래(구체적인 쪽)에 넣는다. 위쪽 층은 문서 수가 적어야 지도로서 쓸모가 있다.

**층을 새로 만들지 않는다.** 여섯 개로 충분하고, 층이 늘면 어디에 뭐가 있는지 아무도 모르게 된다.

## 파일과 링크

- **파일명은 한국어**, 공백 허용, 확장자 없이 부른다
- 링크는 옵시디언 위키링크 `[[문서 이름]]`. 경로 없이 **파일명만** 쓴다
- 그래서 **파일명은 볼트 전체에서 유일**해야 한다
- 프론트매터 없음
- 첫 줄은 `# 문서 이름` (파일명과 같게)
- **아직 없는 문서에 링크해도 된다.** 나중에 그 이름으로 만들면 자동으로 이어진다

## 쓰는 방식

- **표를 먼저 생각한다.** 항목이 셋 이상이면 대개 산문보다 표가 낫다
- 근거를 인용할 때는 인용 블록(`>`)에 출처를 한 줄 붙인다
- 이모지 쓰지 않는다
- 다이어그램은 코드 블록 안의 ASCII로. 이미지 파일을 만들지 않는다
- 길어지면 자른다. 한 문서가 화면 여러 개를 넘어가면 층을 잘못 잡은 것이다

## 근거 없는 것을 쓰지 않는다

여기 적히는 것은 다음 중 하나에서 확인된 것이어야 한다.

- `Source/Project_GJ/` 소스
- `Docs/superpowers/specs/*.md` (설계 결정과 그 이유)
- `Docs/superpowers/plans/*.md`
- `Data/*.csv`, 데이터 테이블
- `Docs/DevGuide.md`

**추측을 사실처럼 쓰지 않는다.** "아마 이럴 것이다"는 아래의 `## 미정`으로 내린다.

## `## 미정` 섹션

모든 문서의 **맨 아래**에 둔다. 안 정해진 것이 없으면 생략해도 되지만, 대부분의 문서에는 있어야 정상이다.

- **질문 형태로 쓴다.** "스테이지 수 미정"이 아니라 "한 런은 몇 스테이지인가?"
- 왜 아직 못 정하는지, 무엇이 먼저 정해져야 하는지를 한 줄 붙이면 좋다
- 정해지면 본문으로 올리고 미정에서 지운다. **결정된 이유를 함께 적는다**

> 뭐가 안 정해졌는지 보이는 것이 이 볼트의 값어치다. 미정 목록이 비어 있는 문서가 많아지면 의심할 일이지 자랑할 일이 아니다.

## 갱신

| 언제 | 무엇을 |
|---|---|
| 새 설계 문서(`specs/`)가 생겼을 때 | 해당 시스템 문서에 규칙과 의도를 반영. 반복되는 판단이면 [[디자인 원칙]]에도 |
| 데이터 테이블 값이 바뀌었을 때 | `03-Content` / `04-Balance` |
| 루프에 칸이 채워지거나 생겼을 때 | [[코어 루프]]의 빈 칸 표 |
| 미정이 결정됐을 때 | 본문으로 올리고 미정에서 삭제 |
| 새 문서를 만들었을 때 | `README`의 층위 지도에 링크 추가 |

**임시 값에는 임시라고 적는다.** 지금 데이터 테이블의 상당수가 검증용 값이다. 그걸 밸런싱 결과처럼 적어두면 나중에 아무도 손대지 못한다.

## 미정

- **여러 사람이 이 볼트를 고치게 될 것인가?** 지금은 1인 개발이라 충돌 규칙이 필요 없다.
- **DevGuide와 이 볼트 중 어느 쪽을 먼저 갱신할 것인가?** 지금은 구현 → DevGuide → 여기 순으로 흘러가고 있지만 명시적으로 정한 적은 없다.
